VeriCross: A Rapid Cross-Verification Platform for Soft Processors using Verilator
==================================================================================

Abstract
--------

This repository contains the source code of a cross-verification platform of soft
processor using Verilator, proposed in the following paper:

(Currently we are submitting the manuscript: to be updated after acceptance)

As the benchmark programs must be compiled for the RV32I instruction set,
a RISC-V cross compiler is required. See `benchmark/README.md` for details.

Verilator is also required to translate SystemVerilog (or Verilog) code into C++
code. We confirmed proper operation with the version (5.020) that can be installed
through apt in Ubuntu 24.04.

----------------------------------------------------------------------------------

Organization of repository
--------------------------

Folders of this repository is organized as follows.

- `benchmark`: modified version of MiBench
  - `binary`: where binary files after cross-compilation are to be saved
  - `input`: input data file (not managed by GitHub due to large files)
  - `source`: MiBench source code
- `core_patch`: patches to kronos and RVCoreP for cross-verification
- `core_patched`: where patched files are to be saved
- `core_verilated`: where files generated by Verilator are to be saved
- `core_wrapper`: wrapper circuits and classes to deal with processors from C++
- `eval`: scripts used for evaluations in the paper
- `kronos`: kronos modified to be accepted by Verilator 5.x (submodule)
- `rvcorep`: RVCoreP modified to be accepted by Verilator 5.x (submodule)
- `sim`: C++ source code of VeriCross

Usage
-----

### Premises

A RISC-V cross compiler has to be available with `riscv32-unknown-elf-gcc`.
If the command name differs, please modify `benchmark/common.mk`.

The common include files of Verilator has to be in `/usr/share/verilator/include`.
If the location differs, please modify `VERILATOR_INCLUDE` of `Makefile`.

### Benchmark input files

The input files of benchmark is out of management of GitHub.
For the first time, please `make -C benchmark input` to download and extract them.

### Building the system

Only you have to do is simply using `make`.
Compilation of benchmarks, translation and building of kronos and RVCoreP,
and building of VeriCross that statically links them will be done with this command. 

### Command line arguments

The VeriCross binary requires the following three command line arguments.
- the folder name where binary and related files are located
- the file name of binary, without extension
- the file name that records the initial state of stack, without `_sp.txt` suffix

In addition to them, it accepts the following optional arguments.
- `-p`: use processor cores only (`-c` option must be specified at the same time)
- `-ccore`, `--core core`: specify the processor core model
- `--list-core`: print the available processor core models and exit
- `-l`: write out the instruction trace to standard output
- `--logfile file`: write out the instruction trace to a file
- `-icount`, `--instruction count`: specify the maximum number of instructions
- `-mN`, `--mismatch N`: if a mismatch is detected, output last N instructions

Please refer to shell scripts in the `eval` folder for examples of command line
arguments.
